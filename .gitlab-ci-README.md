# GitLab CI/CD Pipeline Documentation

## Overview

This GitLab CI/CD pipeline automates the testing, building, and deployment of the Next.js headless storefront application.

## Pipeline Stages

### 1. **Install** 📦
- Installs npm dependencies
- Caches `node_modules` for faster subsequent builds
- Creates artifacts for downstream jobs

### 2. **Lint** 🔍
Three parallel jobs ensure code quality:
- **ESLint**: Enforces code quality rules
- **TypeScript**: Type checking without emitting files
- **Prettier**: Code formatting validation (warning only)

### 3. **Test** 🧪
- **Unit Tests**: Jest/React Testing Library (placeholder)
- **E2E Tests**: Playwright/Cypress (placeholder)
- Generates coverage reports

### 4. **Security** 🔒
Multiple security scanning tools:
- **npm audit**: Dependency vulnerability scanning
- **SonarQube**: Code quality and security analysis
- **OWASP Dependency Check**: Advanced dependency scanning
- **Trufflehog**: Secret detection in codebase

### 5. **Build** 🏗️
- Builds Next.js production bundle
- Generates build metadata
- Creates deployment artifacts
- Caches `.next` directory

### 6. **Deploy** 🚀
- **Staging**: Auto-deploy to staging environment (manual trigger)
- **Production**: Deploy to production (manual approval required)
- **Rollback**: Emergency rollback capability
- Health checks and smoke tests

## Required GitLab CI/CD Variables

### Environment Variables
Configure these in GitLab: **Settings → CI/CD → Variables**

#### Build Variables
```
SITE_URL                    # Public site URL (e.g., https://your-domain.com)
GRAPHQL_ENDPOINT           # WooCommerce GraphQL endpoint
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY  # Stripe public key (if using payments)
```

#### Security Variables (if using SonarQube)
```
SONAR_HOST_URL             # SonarQube server URL
SONAR_TOKEN               # SonarQube authentication token
```

#### Deployment Variables (choose based on your hosting)

**Option 1: Vercel**
```
VERCEL_TOKEN              # Vercel authentication token
VERCEL_SCOPE              # Vercel team/organization scope
```

**Option 2: Netlify**
```
NETLIFY_AUTH_TOKEN        # Netlify authentication token
NETLIFY_SITE_ID           # Netlify site ID
```

**Option 3: Custom Server**
```
SSH_PRIVATE_KEY           # SSH private key for server access
DEPLOY_USER               # SSH username
DEPLOY_HOST               # Server hostname/IP
DEPLOY_PATH               # Deployment directory path
```

**Option 4: Docker Registry**
```
CI_REGISTRY_IMAGE         # Docker registry image name
DOCKER_USERNAME           # Docker registry username
DOCKER_PASSWORD           # Docker registry password
```

### Protected/Masked Variables
Mark the following as **Protected** and **Masked**:
- All tokens and passwords
- SSH keys
- API keys

## Pipeline Triggers

### Automatic Triggers
- **All Branches**: Runs install, lint, test, security, build stages
- **Main Branch**: Full pipeline including production build
- **Develop Branch**: Full pipeline including staging deployment option
- **Merge Requests**: Runs lint, test, and security stages
- **Tags**: Full pipeline for versioned releases

### Manual Triggers
- **Staging Deployment**: Manual trigger required
- **Production Deployment**: Manual approval required
- **Performance Testing**: Manual trigger
- **Bundle Analysis**: Manual trigger
- **Rollback**: Emergency manual trigger

## Deployment Options

### 1. Vercel (Recommended for Next.js)
Uncomment the Vercel section in `.gitlab-ci.yml`:
```yaml
- npm install -g vercel
- vercel deploy --token=$VERCEL_TOKEN --scope=$VERCEL_SCOPE --prod
```

### 2. Netlify
Uncomment the Netlify section:
```yaml
- npm install -g netlify-cli
- netlify deploy --dir=.next --site=$NETLIFY_SITE_ID --auth=$NETLIFY_AUTH_TOKEN
```

### 3. Custom Server with PM2
Uncomment the PM2 section:
```yaml
- rsync -avz .next/ $DEPLOY_USER@$DEPLOY_HOST:$DEPLOY_PATH/.next/
- ssh $DEPLOY_USER@$DEPLOY_HOST "cd $DEPLOY_PATH && npm ci --production && pm2 reload ecosystem.config.js"
```

### 4. Docker Container
Uncomment the Docker section:
```yaml
- docker build -t $CI_REGISTRY_IMAGE:production .
- docker push $CI_REGISTRY_IMAGE:production
```

## Artifacts

### Build Artifacts (1 week retention)
- `.next/` - Next.js build output
- `public/` - Static assets
- `package.json` & `package-lock.json`

### Test Artifacts (30 days retention)
- `coverage/` - Code coverage reports
- Test results in JUnit format

### Security Artifacts (7 days retention)
- `dependency-check-report/` - OWASP scan results
- `trufflehog-report.json` - Secret detection results

## Caching Strategy

### Node Modules Cache
- **Key**: Based on `package-lock.json` hash
- **Paths**: `.npm/`, `node_modules/`
- **Policy**: Pull-push (download and upload)

### Build Cache
- **Paths**: `.next/cache/`
- **Improves**: Subsequent build performance

## Performance Optimizations

1. **npm ci** instead of `npm install` - Faster, more reliable
2. **Dependency caching** - Speeds up subsequent builds
3. **Build artifact reuse** - Shared across deployment jobs
4. **Parallel jobs** - Lint jobs run concurrently
5. **Conditional execution** - Jobs only run when needed

## Best Practices

### Branch Protection
1. Protect `main` branch
2. Require passing pipelines for merges
3. Require code review approvals

### Security
1. Never commit secrets to repository
2. Use GitLab CI/CD variables for sensitive data
3. Mark sensitive variables as "Masked" and "Protected"
4. Rotate credentials regularly

### Testing
1. Run full test suite on main/develop branches
2. Run lint and critical tests on feature branches
3. Use merge request pipelines for code review

## Troubleshooting

### Common Issues

#### "npm ci" Fails
```bash
# Solution: Clear cache
rm -rf node_modules .npm package-lock.json
npm install
```

#### Build Artifacts Not Found
```bash
# Check if artifacts were created
ls -la .next/
# Verify artifact paths in job configuration
```

#### Deployment Hangs
```bash
# Check timeout settings
# Increase DEPLOY_TIMEOUT variable
# Check server connectivity
```

#### SonarQube Analysis Fails
```bash
# Verify SONAR_HOST_URL and SONAR_TOKEN are set
# Check SonarQube server is accessible
# Review sonar-scanner logs
```

## Customization

### Adding New Jobs
```yaml
my_custom_job:
  stage: test
  needs:
    - install_dependencies
  script:
    - echo "Running custom job"
  tags:
    - docker
```

### Adding New Environments
```yaml
deploy:qa:
  stage: deploy
  environment:
    name: qa
    url: https://qa.your-domain.com
  script:
    - echo "Deploying to QA"
  only:
    - develop
```

### Custom Deployment Scripts
Create deployment scripts in `scripts/` directory:
```bash
scripts/
├── deploy-vercel.sh
├── deploy-netlify.sh
└── health-check.sh
```
